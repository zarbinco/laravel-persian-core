# Laravel Persian Core

[English README](README.md)

با این بسته می‌توانید متن فارسی، ارقام و شمارهٔ موبایل ایران را در برنامه‌های لاراول یکدست کنید، مبلغ‌های ریالی و تومانی را بخوانید و قالب‌بندی کنید و ورودی‌های رایج ایرانی را اعتبارسنجی کنید. بسته بانک را هم از روی پیش‌شمارهٔ کارت یا کد بانک در شمارهٔ شبا پیدا می‌کند.

پردازش پرداخت، استعلام بانکی، ارسال پیامک، تقویم جلالی، صدور فاکتور و حسابداری خارج از محدودهٔ بسته‌اند.

## سازگاری

این راهنما برای نسخهٔ در دست انتشار `v1.0.0` است.

| نسخهٔ لاراول | نسخه‌های PHP |
| --- | --- |
| لاراول ۱۲ | `8.2`، `8.3`، `8.4` و `8.5` |
| لاراول ۱۳ | `8.3`، `8.4` و `8.5` |

در Composer، نیازمندی PHP برابر `^8.2` است و مؤلفه‌های Illuminate باید در بازهٔ `^12.0` یا `^13.0` باشند. نیازمندی PHP هر نسخهٔ لاراول هم باید رعایت شود. برای ارتقا از نسخهٔ منتشرشدهٔ `v0.2.0`، [راهنمای ارتقا](UPGRADE.md) را ببینید.

## نصب

```bash
composer require zarbinco/laravel-persian-core
```

لاراول با سازوکار کشف خودکار بسته‌ها، سرویس‌پراوایدر بسته و نام مستعار `Persian` را ثبت می‌کند.

## انتشار تنظیمات و ترجمه‌ها

تنظیمات پیش‌فرض و پیام‌های اعتبارسنجی به‌صورت خودکار بارگذاری می‌شوند. برای سفارشی‌سازی، می‌توانید فایل تنظیمات را در `config/persian-core.php` و ترجمه‌ها را در `vendor/persian-core` زیر مسیر زبان برنامه منتشر کنید.

```bash
php artisan vendor:publish --tag=persian-core-config
php artisan vendor:publish --tag=persian-core-lang
```

دستور نصب بسته هر دو را یک‌جا منتشر می‌کند.

```bash
php artisan persian-core:install
```

برای بازنویسی فایل‌های منتشرشده از گزینهٔ `--force` استفاده کنید. دستور `persian-core:doctor` تنظیمات را بررسی می‌کند و `persian-core:about` اطلاعات بسته و محیط اجرا را نمایش می‌دهد.

## متن، عدد و شمارهٔ موبایل

نرمال‌سازی متن، حروفی مثل `ي` و `ك` را به شکل فارسی برمی‌گرداند، فاصله‌ها را یکدست می‌کند و بعضی نویسه‌های نامرئی را حذف می‌کند. حالت پایه نیم‌فاصله را حفظ می‌کند. با تنظیمات پیش‌فرض، `forStorage()` و میان‌بر آن `clean()` رقم‌ها را برای ذخیره‌سازی به انگلیسی تبدیل می‌کنند و `forDisplay()` آن‌ها را به فارسی نمایش می‌دهد.

```php
use Zarbinco\PersianCore\Facades\Persian;

Persian::text('علي كاظمي')->normalize();
// علی کاظمی

Persian::number('۱۲۳٤٥۶')->toEnglish();
// 123456

Persian::clean('علي كاظمي شماره ۰۹۱۲۱۲۳۴۵۶۷');
// علی کاظمی شماره 09121234567

Persian::normalize('شماره 09121234567')->forDisplay();
// شماره ۰۹۱۲۱۲۳۴۵۶۷

Persian::mobile('۰۹۱۲ ۱۲۳ ۴۵۶۷')->international();
// +989121234567

Persian::mobile('۰۹۱۲ ۱۲۳ ۴۵۶۷')->mask();
// 0912***4567
```

توابع موبایل ممکن است از ورودی نامعتبر هم رشته‌ای پاک‌سازی‌شده برگردانند. پیش از ذخیرهٔ شماره‌ای که باید معتبر باشد یا پوشاندن بخشی از آن با `mask()`، از قاعدهٔ `IranianMobile` استفاده کنید. الگوی پوشاندن رقم‌ها از طریق `mobile.iran.mask_pattern` قابل تنظیم است.

## جست‌وجو

برای متن ذخیره‌شده در نمایه و عبارت جست‌وجوی کاربر از یک نرمال‌ساز استفاده کنید. در تنظیمات پیش‌فرض، علائم نگارشی و نیم‌فاصله به فاصله تبدیل می‌شوند و رقم‌ها به شکل انگلیسی درمی‌آیند. جداکنندهٔ هزارگان از عددی با گروه‌بندی درست، مثل `۱۲٬۵۰۰`، حذف می‌شود. فاصلهٔ بین دو عدد جدا حفظ می‌شود و `1,000 200` به `1000 200` تبدیل می‌شود.

```php
Persian::search('آب‌میوه سن‌ایچ ۱۲٬۵۰۰ تومان!')->normalize();
// اب میوه سن ایچ 12500 تومان

Persian::search('آب‌میوه سن‌ایچ')->tokens();
// ['اب', 'میوه', 'سن', 'ایچ']
```

تابع `Persian::searchable($value)` همان متن نرمال‌شده را مستقیم برمی‌گرداند. انتخاب موتور جست‌وجو، شیوهٔ تطبیق و رتبه‌بندی نتیجه‌ها بر عهدهٔ برنامه است.

## مبلغ به تومان و ریال

مبلغ‌ها به واحد کامل ریال یا تومان خوانده می‌شوند. متد `value()` عددی از نوع `int` برمی‌گرداند. برای ورودی نامعتبر یا مبلغ خارج از بازهٔ اعداد صحیح PHP، نتیجه `null` است.

```php
Persian::money('قیمت: ۱٬۲۵۰٬۰۰۰ تومان')->value();
// 1250000

Persian::money('۱۲٬۵۰۰٬۰۰۰ ریال')->detectedCurrency();
// rial

Persian::money(1250000)->format();
// ۱,۲۵۰,۰۰۰ تومان

Persian::money(12500000)->fromRial()->toToman();
// 1250000
```

رقم‌های فارسی، عربی و انگلیسی پذیرفته می‌شوند. بخش اعشاری اگر فقط صفر داشته باشد، مثل `۱۲٫۰۰`، پذیرفته می‌شود. کسرهای غیرصفر مثل `۱۲٫۵`، گروه‌بندی نادرست، چند مبلغ در یک ورودی و شکل‌های دیگر رقم در یونیکد رد می‌شوند. فاصلهٔ افقی در گروه‌بندی درست می‌تواند جداکنندهٔ هزارگان باشد. برای نمونه، `100 200` به‌صورت `100200` خوانده می‌شود.

متد `format()` رشته برمی‌گرداند و برای ورودی غیرقابل‌خواندن نتیجهٔ آن `''` است. رشتهٔ معتبر خارج از بازهٔ `int` هم قابل نمایش است. واحدی که به `format()` می‌دهید فقط برچسب مبلغ را مشخص می‌کند. برای تبدیل، از `toToman()` یا `toRial()` و برای نمایش مبلغ تبدیل‌شده از `formatToman()` یا `formatRial()` استفاده کنید.

نرخ پیش‌فرض تبدیل، ۱۰ ریال برای هر تومان است و در `money.rial_to_toman_rate` تنظیم می‌شود. در تبدیل ریال به تومان، بخش باقی‌مانده حذف می‌شود. تبدیل تومان به ریال در صورت سرریز عدد صحیح، `null` برمی‌گرداند.

## تشخیص بانک از روی کارت یا شبا

تشخیص بانک بر اساس پیش‌شمارهٔ کارت (`BIN/IIN`) یا کد بانک در شبا و با داده‌های همراه بسته انجام می‌شود. اگر کد یا پیش‌شماره در داده‌های محلی پیدا نشود، نتیجه `null` است.

```php
Persian::card('6037991234567890')->bankSlug();
// melli

Persian::sheba('IR170170000000000000000000')->bankNameFa();
// بانک ملی ایران
```

برای اعتبارسنجی ساختار و رقم کنترلی از `IranianCardNumber` و `IranianSheba` استفاده کنید. استعلام وجود یا مالکیت حساب، مالکیت کارت و وضعیت لحظه‌ای آن‌ها به سرویس بانکی جداگانه نیاز دارد.

## اعتبارسنجی در لاراول

از قواعد لاراول برای رد ورودی نامعتبر پیش از ذخیره‌سازی استفاده کنید. مقدار خالی با تنظیمات پیش‌فرض پذیرفته می‌شود. برای فیلد اجباری، قاعدهٔ `required` لاراول را هم اضافه کنید.

```php
use Zarbinco\PersianCore\Rules\IranianMobile;
use Zarbinco\PersianCore\Rules\PersianAlpha;

$request->validate([
    'name' => ['required', new PersianAlpha()],
    'mobile' => ['required', new IranianMobile()],
]);
```

حالت سخت‌گیرانه برای موبایل، کد ملی، کد پستی، شمارهٔ کارت، شبا و مبلغ به‌صورت پیش‌فرض فعال است. در این حالت، کل ورودی باید با قالب قاعده سازگار باشد. برای نمونه، `PersianMoneyAmount` متن `قیمت: ۱۵۰۰ تومان` را رد می‌کند، اما `new PersianMoneyAmount(strict: false)` می‌تواند همان مبلغ را از متن بپذیرد. با غیرفعال‌کردن حالت سخت‌گیرانه، بررسی‌هایی مثل قابل‌خواندن بودن مبلغ و قرارگرفتن آن در بازهٔ `int` همچنان انجام می‌شوند.

قاعدهٔ `IranianCardNumber` به‌طور پیش‌فرض الگوریتم لُون (`Luhn`) را اعمال می‌کند. اگر شمارهٔ کارت باید پیش‌شماره‌ای در داده‌های همراه بسته داشته باشد، گزینهٔ `validation.iranian_card_number.require_iranian_bin` را فعال کنید.

فهرست کامل قواعد و جزئیات تنظیمات در [راهنمای انگلیسی](README.md#validation) آمده است.

## توسعه و جایگزینی سرویس‌ها

برای جایگزینی یک سرویس، قرارداد مربوط را در سرویس‌پراوایدر برنامه به پیاده‌سازی دلخواه متصل کنید. این اتصال باید پیش از اولین استفاده از `Persian` برقرار شود.

```php
use App\Support\CustomTextNormalizer;
use Zarbinco\PersianCore\Contracts\PersianTextNormalizerContract;

$this->app->bind(PersianTextNormalizerContract::class, CustomTextNormalizer::class);
```

پیاده‌سازی سفارشی باید ورودی‌ها، نوع خروجی و رفتار تعریف‌شده در قرارداد را حفظ کند.
